# SuperSplat Arena Spike

Gaussian Splat arenas are optional published maps for `1v1` and `2v2`. The lobby, matchmaking, voice casting, keyboard fallback, Render deploys, and server-authoritative combat still use the existing game systems. The lightweight arena remains the fallback whenever no compatible splat map is published or a splat/preset fails to load.

## What SuperSplat Is

[PlayCanvas SuperSplat](https://github.com/playcanvas/supersplat) is a free browser-based editor for inspecting, cleaning, optimizing, and publishing 3D Gaussian Splat captures. PlayCanvas describes SuperSplat as a production workflow tool that runs in the browser, and their current Gaussian Splat docs recommend SOG for runtime delivery because it is much smaller and faster to load than raw PLY.

Gaussian Splats are a renderer-friendly scene representation made from many translucent 3D Gaussians. They are excellent for photorealistic captured environments, but they are not gameplay geometry.

## VibeJam Use

For VibeJam, a splat arena should be a visual-only environment layer behind or around the existing game systems:

- Players stay normal networked entities.
- Spells, projectiles, hitboxes, HP, mana, cooldowns, and damage stay normal client/server systems.
- The Colyseus room remains authoritative for movement, casts, damage, phase changes, and winners.
- The splat does not decide where players can walk or what projectiles hit.

This means the splat can fail, load late, or be replaced without invalidating gameplay.

## Why Collision Is Separate

A Gaussian Splat is not a reliable collision source. It is a visual field, not a clean triangle mesh with stable surfaces, normals, nav zones, or gameplay bounds. Dense captures can contain floaters, holes, transparent regions, camera artifacts, and details that look solid but should not block a player.

Gameplay collision needs separate invisible proxy data:

- A hand-authored or generated GLB collision mesh.
- A generated voxel collision dataset: `.voxel.json` metadata plus `.voxel.bin` data.
- Simple arena bounds for server-side movement limits.
- Spawn points and gameplay regions defined in preset JSON.
- Optional future voxel or proxy data generated by tooling such as [`@playcanvas/splat-transform`](https://github.com/playcanvas/splat-transform), which can read and write SOG-related formats and export collision-oriented data.

The current spike keeps the SOG visual-only, but lets the experimental `splat-test` preset provide separate server-side bounds, spawn points, generated voxel collision, simple invisible wall blockers, voxel eraser zones, and optional climbable ladder triggers. The generated GLB remains a visual/debug guide only; voxel data plus manual preset boxes are the gameplay collision sources.

## Recommended Pipeline

1. Capture or generate the Gaussian Splat source.
2. Clean, crop, transform, and optimize it in SuperSplat.
3. Export a runtime asset as SOG or another compressed delivery format.
4. Create or generate a collision mesh GLB that matches the playable floor, walls, and blockers.
5. Load the splat visually and lazily only for splat-enabled arenas.
6. Load the collision mesh invisibly as a gameplay/debug proxy.
7. Place spawns, gameplay bounds, scale, rotation, and offset in an arena preset JSON file.

PlayCanvas docs describe PLY as the source/interchange format and SOG as the runtime delivery format. The same docs show direct PlayCanvas Engine loading of a `.sog` asset through a `gsplat` component.

## File Size Risks

Splats can be far larger than the current primitive arena. Raw captures may be hundreds of MB or several GB before optimization. Even compressed web-ready splats can be tens of MB for large environments.

VibeJam protections:

- Never import splat assets into TypeScript.
- Never bundle splat data into JS.
- Keep splats under `client/public/splats/` or an external CDN URL.
- Lazy-load only after the experimental portal is selected.
- Keep the lightweight arena as the default and fallback.
- Avoid blocking loading screens.
- Document every local sample size before adding it to the repo.

## Lazy Loading Strategy

The game should mount the normal lightweight arena immediately, then attempt the splat visual layer in the background:

1. Player enters the normal `1v1` or `2v2` queue.
2. The Colyseus room is filtered only by `mode`.
3. The server randomly selects one published splat preset from `client/public/arena-presets/splat-catalog.json` whose `enabledModes` includes that mode.
4. The server writes the selected `arenaPresetId`, `arenaPresetUrl`, and `arenaDisplayName` into `GameState`.
5. The client mounts the lightweight arena first, then fetches the server-selected preset URL.
6. The client lazy-loads the splat renderer path and the selected `/splats/*.sog` file only after the match starts.
7. If no compatible map is published, or the preset/SOG fails, keep the lightweight arena and continue the match.

The timeout is a UX guard only. It must not affect matchmaking, server simulation, damage, or controls.
The current nonblocking timeout is 20 seconds. Current maps are about 13.72 MiB and 6.81 MiB.

## Fallback

Failure must be boring:

- If the preset is missing, use the lightweight arena.
- If the SOG URL fails, use the lightweight arena.
- If PlayCanvas/CDN loading fails, use the lightweight arena.
- If the collision GLB is missing, use simple preset bounds.
- If the user returns to lobby, dispose any splat canvas and restore the normal renderer background.

## Runtime Decision

Evaluated options:

- A Three.js Gaussian Splat renderer: attractive because the game already uses Three.js, but current SOG support is better aligned with PlayCanvas.
- A PlayCanvas/SuperSplat visual layer: least invasive for SOG because PlayCanvas Engine supports `gsplat` assets, including `.sog`.
- Documentation-only future pipeline: safest, but it would not prove whether a splat layer can coexist with current gameplay.

This spike uses option B as an optional visual layer. The Three.js game remains the gameplay renderer, and PlayCanvas is loaded only for the experimental splat arena path. This keeps the VibeJam widget, default arena, and existing multiplayer flow intact.

## Preset Contract

Arena presets live in `client/public/arena-presets/`. A splat preset defines:

```json
{
  "presetId": "businesspark-belp-1og-ost",
  "arenaId": "splat-test",
  "displayName": "Businesspark Belp 1OG Ost",
  "type": "splat",
  "splatUrl": "/splats/businesspark-belp-1og-ost.sog",
  "splatFileSizeBytes": 14381152,
  "enabledModes": ["1v1"],
  "collisionMeshUrl": null,
  "voxelCollisionUrl": "/collision/businesspark-belp-1og-ost.voxel.json",
  "spawnPoints": [
    { "x": -5.5, "y": 0, "z": 0, "rotY": -1.5707963268 },
    { "x": 5.5, "y": 0, "z": 0, "rotY": 1.5707963268 }
  ],
  "spawnPointsByMode": {
    "1v1": [
      { "x": -5.5, "y": 0, "z": 0, "rotY": -1.5707963268 },
      { "x": 5.5, "y": 0, "z": 0, "rotY": 1.5707963268 }
    ],
    "2v2": [
      { "x": -5.5, "y": 0, "z": -1.25, "rotY": -1.5707963268 },
      { "x": 5.5, "y": 0, "z": 1.25, "rotY": 1.5707963268 },
      { "x": -5.5, "y": 0, "z": 1.25, "rotY": -1.5707963268 },
      { "x": 5.5, "y": 0, "z": -1.25, "rotY": 1.5707963268 }
    ]
  },
  "bounds": { "minX": -8, "maxX": 8, "minZ": -6, "maxZ": 6 },
  "scale": 1,
  "rotation": { "x": 0, "y": 0, "z": 0 },
  "offset": { "x": 0, "y": 0, "z": 0 },
  "floorY": 0,
  "collisionErasers": [],
  "collisionWalls": [
    {
      "id": "example-ladder",
      "x": 0,
      "z": -2,
      "width": 1.2,
      "depth": 0.45,
      "height": 3,
      "rotY": 0,
      "climbable": true
    }
  ]
}
```

`enabledModes` controls whether the published map can be selected for `1v1`, `2v2`, or both. `spawnPointsByMode` stores two spawns for `1v1` and four spawns for `2v2`; legacy `spawnPoints` remains as the `1v1` fallback.

The server, not the client, selects the final map for multiplayer. The client no longer sends local autosave collision config to Colyseus, so everyone in the same room loads the same published preset. The server keeps movement, projectiles, hits, HP, and damage authoritative, and uses the selected preset's `bounds`, mode-specific spawns, `voxelCollisionUrl`, `collisionWalls`, and `collisionErasers`. If no map is enabled for a mode, that mode falls back to the lightweight arena.

## Tuning

Tune each asset through its map preset:

- `client/public/arena-presets/businesspark-belp-1og-ost.json`
- `client/public/arena-presets/moscow-novoslobodskaya-dollhouse.json`

- `scale`: uniform splat scale applied in PlayCanvas.
- `rotation`: Euler rotation in degrees, applied as `{ "x": 0, "y": 0, "z": 0 }`.
- `offset`: world-space splat offset in VibeJam coordinates.
- `floorY`: local fallback floor height used by the calibration mode and invisible fallback proxy.
- `bounds`: fallback playable floor and wall proxy, plus the documented gameplay area.
- `enabledModes`: matchmaking destinations for this map, using `["1v1"]`, `["2v2"]`, both, or `[]` to disable the map.
- `spawnPoints`: legacy `1v1` spawn fallback.
- `spawnPointsByMode`: authoritative published spawns by mode: two entries for `1v1`, four for `2v2`.
- `voxelCollisionUrl`: optional generated voxel collision metadata URL, always under `/collision/*.voxel.json`. The matching `.voxel.bin` is fetched next to it. This is the automatic collision base used by calibration and `splat-test` multiplayer.
- `collisionMeshUrl`: optional generated GLB guide. It can be shown in calibration, but it is not authoritative physics.
- `collisionWalls`: optional invisible manual proxy volumes that add blockers or ladders on top of the voxel base. Each wall has `id`, `x`, `z`, `width`, `depth`, `height`, `rotY`, and optional `climbable`. Normal wall `height` is gameplay height: low boxes can be jumped over or landed on, while taller walls still block horizontal movement. `climbable: true` keeps the ladder behavior separate.
- `collisionErasers`: optional invisible boxes that subtract the generated voxel collision inside that volume. They do not disable manual walls or ladders.

For first-pass tuning, use local calibration mode:

```txt
http://127.0.0.1:<port>/?calibrateSplat=1
```

You can also press `F8` from the lobby. Calibration mode does not enter Colyseus matchmaking, does not need a second player, and does not show the match-ended panel. It loads the same SOG lazily, lets a local player/camera move around, supports a normal character jump with `Space`, and exposes live controls for `scale`, `offset`, `rotation`, `floorY`, `bounds`, mode-specific spawn points, and invisible walls.

Calibration mode also has a map selector. Pick a map, tune it, choose `Use in 1v1` and/or `Use in 2v2`, then switch `Editing spawns` between `1v1` and `2v2` to place the correct spawn set. Press `Save Config` to persist the chosen map and settings in browser `localStorage`. Press `Publish Map To Game` in local/dev to write `client/public/arena-presets/<presetId>.json`, update `client/public/arena-presets/splat-catalog.json`, and mirror those files into `client/dist` when it exists. Render will use those published JSON files after deploy.

Every live edit autosaves locally and keeps a five-entry per-preset history. `Reset` first stores a `before-reset` backup, then clears the visible calibration to the loaded preset values. Use `Restore Last` to recover the newest autosave/manual/reset backup, and `Restore Backup` to recover the newest manual save or before-reset snapshot. Use `Add Wall` to create an invisible blocker at the player position, `Wall Here` to move the selected wall to the player, `Toggle Ladder` to convert the selected wall into a climbable ladder trigger or back into a normal blocker, and `Delete Wall` to remove it. Wall `height` changes the debug box height and the gameplay proxy height: low walls work like boxes that can be jumped over or landed on; taller walls block movement and projectiles. Ladder triggers draw visible rungs in calibration, do not block horizontal movement, and let the player climb with `W` or `Space` and descend with `S`. Walls and ladder triggers render only as calibration guides; they are invisible in matches. Use `Copy Preset JSON` when you want to inspect or paste the tuned preset manually. If the splat appears too large, too close, or blurry, tune `scale` and `offset` first, then adjust `floorY`, bounds, and wall blockers.

## Voxel Auto Collision Upgrade

`@playcanvas/splat-transform` can generate voxel collision data and a `.collision.glb` guide from a SOG/PLY source. Magic Casters now uses the generated `.voxel.json/.voxel.bin` as the automatic collision base for `splat-test` rooms. The generated `.collision.glb` stays a visual calibration guide, not physics.

Runtime collision resolves bounds/floor, generated voxel collision, then manual blockers/ladders. Normal walls add hand-authored blockers according to their height; `climbable: true` volumes behave like ladder triggers; `collisionErasers` subtract only the voxel layer where the auto collision blocks incorrectly.

Generate a guide mesh with:

```bash
npm run splat:collision -- --input client/public/splats/<arena>.sog --arena <arena>
```

The wrapper calls `npx @playcanvas/splat-transform@latest` with voxel output and `--collision-mesh`. By default it targets resolution `256` and writes:

```txt
client/public/collision/<arena>.voxel.json
client/public/collision/<arena>.voxel.bin
client/public/collision/<arena>.collision.glb
```

Then update the preset:

```json
"voxelCollisionUrl": "/collision/<arena>.voxel.json",
"collisionMeshUrl": "/collision/<arena>.collision.glb"
```

In calibration, enable `Show Generated Collision` to display the generated GLB as a translucent guide. `Generate Auto Collision` can run the same wrapper through a local/dev-only endpoint, then activates `voxelCollisionUrl`. It no longer creates 64 visible `auto-` walls. Use manual `collisionWalls` only for blockers/ladders you want to add, and `Eraser Zones` for places where the generated voxel collision should be removed. `Clear Auto Collision` disables `voxelCollisionUrl`, removes legacy `auto-` walls if present, and when the local endpoint is available deletes generated voxel/GLB files. It keeps manual walls, ladders, and erasers.

The splat must remain visual-only. Do not derive authoritative hits, damage, player movement, or spell collision directly from the SOG. Do not ship source `.ply` files from `client/public/`.

## Local Test

1. Run `npm install` if dependencies are missing.
2. Run `npm run build`.
3. Run `npm run start`.
4. Open `http://127.0.0.1:3001` or the port set by `PORT`.
5. Enter the `1v1 Duel`, `2v2 Team Duel`, or `Realistic Arena Test` portal.
6. Join enough clients for that mode so the match starts.
7. Confirm the debug overlay shows:
   - `arena splat-test`
   - `splat loading`, then `splat loaded` or `splat fallback`
   - `splatUrl ...businesspark-belp-1og-ost.sog` or `...moscow-novoslobodskaya-dollhouse.sog`
  - `collision fallback` or `collision mesh`
  - `voxel loaded` when the published preset has `voxelCollisionUrl`

`1v1 Duel` and `2v2 Team Duel` now use the server-selected published map pool when compatible maps exist. If no map is enabled for a mode, that mode should show no splat debug data and should not request a SOG.

## Render Test

1. Commit and deploy with the existing Render build command: `npm install && npm run build`.
2. Open the Render URL.
3. Confirm the lobby and VibeJam widget appear.
4. Confirm 1v1 and 2v2 can still start.
5. Confirm the SOG request is for the server-selected file under `/splats/` and happens only after the match starts.
7. If the request fails or times out, confirm gameplay continues on the lightweight fallback.
