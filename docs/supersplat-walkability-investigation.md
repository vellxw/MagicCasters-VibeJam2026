# SuperSplat Walkability Investigation

## Scope

This investigation checks whether the Realistic Arena Test SOG assets contain usable gameplay collision or walkability data, and whether local SuperSplat / PlayCanvas tooling should be integrated into Magic Casters runtime.

The answer for this asset is: the SOG is visual-only. Magic Casters should use only separate collision data: generated voxel collision, manual blockers/ladders, eraser zones, and fallback floor/bounds.

## Local Tooling Check

No local SuperSplat editor repo was found in the project folder or the nearby desktop workspace paths checked during this spike. The production client was not changed to include the SuperSplat editor.

`@playcanvas/splat-transform` is not bundled into the game and is not a production dependency. The project now has an offline wrapper script, `npm run splat:collision`, which calls `npx @playcanvas/splat-transform@latest` only when a developer wants to generate collision guide assets. The current SOG metadata says these assets were generated by:

```txt
splat-transform v1.10.2
```

No local source `.ply` file was found. The wrapper can work from the `.sog` in `client/public/splats/`, but any future `.ply` source should stay outside `client/public/` so it is not served to players.

## What "Walkable" Means In The Viewer

SuperSplat and the PlayCanvas viewer can make a scene feel walkable because the viewer camera can move through or around the captured space. That is viewer navigation, not proof that the SOG contains physics data.

For Magic Casters, walkability must mean one of these separate gameplay assets exists:

- A collision GLB guide generated or authored separately.
- A nav mesh or floor proxy.
- A voxel or signed-distance representation deliberately exported for collision.
- Preset-authored bounds and obstacle boxes.

None of those were found in the current SOG.

## Runtime Decision

Magic Casters should continue to use:

- SOG: visual layer only.
- Preset `bounds`: fallback playable clamp and invisible floor/walls.
- Preset `floorY`: local calibration floor height.
- Preset `spawnPoints`: local calibration and future arena spawning metadata.
- Optional `collisionMeshUrl`: invisible GLB guide/proxy loaded by the client for calibration/debug.
- Optional `voxelCollisionUrl`: generated `.voxel.json/.voxel.bin` auto-collision loaded by client calibration and by the server for `splat-test`.
- Preset `collisionWalls`: manual blockers/ladders sent to the server for `splat-test`.
- Preset `collisionErasers`: manual boxes that subtract generated voxel collision only.

Do not derive authoritative player movement, spell hits, or damage from the SOG.

## Calibration Mode

Use the local-only calibration route:

```txt
http://127.0.0.1:<port>/?calibrateSplat=1
```

Or press `F8` from the lobby.

This mode:

- does not enter Colyseus matchmaking,
- does not need another player,
- does not show match results,
- lazy-loads the same Realistic Arena Test SOG,
- lets a local player/camera move inside preset bounds,
- exposes live controls for scale, offset, rotation, floorY, bounds, spawn A, spawn B, invisible walls, wall height, and ladder toggles,
- lets low wall boxes be jumped over or landed on while tall walls block movement,
- can show a generated collision GLB as a translucent guide when `collisionMeshUrl` exists,
- can generate and activate `.voxel.json/.voxel.bin` through the local/dev-only `Generate Auto Collision` button,
- no longer turns auto collision into 64 visible editable walls,
- can add manual blockers/ladders on top of voxel collision,
- can add eraser zones to subtract voxel collision in bad areas,
- can disable voxel collision with `Clear Auto Collision` without deleting manual walls, ladders, or erasers,
- can switch maps,
- can save the tuned config in browser `localStorage`,
- can copy the tuned preset JSON to clipboard.

## Collision Guide Path

Generate an approximate collision guide from a SOG with:

```bash
npm run splat:collision -- --input client/public/splats/<arena>.sog --arena <arena>
```

The wrapper uses `splat-transform` voxel output plus `--collision-mesh`, with target resolution `256` by default. It writes:

```txt
client/public/collision/<arena>.voxel.json
client/public/collision/<arena>.voxel.bin
client/public/collision/<arena>.collision.glb
```

Then update:

```json
"voxelCollisionUrl": "/collision/<arena>.voxel.json",
"collisionMeshUrl": "/collision/<arena>.collision.glb"
```

The collision GLB should be low-detail and aligned to the calibrated SOG transform. It is a visual calibration guide only. The voxel pair is the automatic collision base; editable `collisionWalls` add blockers/ladders; editable `collisionErasers` remove bad voxel areas. The SOG remains visual-only.
